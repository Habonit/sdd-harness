# round-start · spec 쓰기

라운드의 첫 단계다. 이번 라운드에서 **무엇을** 만들지 `spec.md` 로 정하고 멈춘다.

## 0. 규칙 먼저
- 프로젝트 루트의 `CLAUDE.md` 를 읽는다. 문서 위치, 코드 규칙, 라운드 종료 조건은 거기에 있다. 이 스킬보다 `CLAUDE.md` 가 우선한다.

## 1. 이번 라운드 찾기
- 인자로 라운드가 주어졌으면(`$ARGUMENTS`) 그 라운드를 쓴다.
- 아니면 `docs/ROADMAP.md` 의 라운드 표에서 위에서부터 처음으로 상태가 `완료` 가 아닌 라운드를 고른다.
- 모든 라운드가 `완료` 면 멈추고 사람에게 묻는다. ROADMAP 에 없는 라운드를 스스로 지어내지 않는다.
- `docs/roundNN/spec.md` 가 이미 있으면 덮어쓰지 않고 사람에게 어떻게 할지 묻는다.

## 2. 읽을 것
1. `docs/ROADMAP.md`: 이번 라운드의 목표와 라운드 메모
2. `docs/SSOT.md`: 지금 서비스의 API, 데이터 모델, 규칙. 남은 어긋남 표시도 본다
3. 바로 앞 라운드의 `spec.md` · `plan.md` · `review.md`
   - 특히 review 의 "다음 라운드로 넘기는 것", 회고의 "다음 라운드에 추가할 규칙 (제안)"
4. 필요하면 지금 코드를 읽어 SSOT 와 맞는지 확인한다. 읽기만 한다.

## 3. `docs/roundNN/spec.md` 쓰기
지난 라운드 spec 과 같은 모양으로 쓴다. 기본 틀:

```
# roundNN spec · <주제>

## 목표
## 요구사항          (데이터 · API 별로. 빈 값 · null · 여러 값 · 경계값을 어떻게 할지 정한다)
## 범위 밖
## 선행 정리 (이월분) (지난 review 에서 넘어온 것 중 이번에 하는 것. 없으면 "없음")
## 완료 기준 (테스트로 확인)
```

- 요구사항은 테스트로 확인할 수 있게 쓴다. "적절히" · "알맞게" 같은 말은 쓰지 않는다.
- 빈 값, `null`, 같은 값 여러 번, 경계값(최소 · 최대 · 하나 넘침), 없는 값처럼 spec 이 비기 쉬운 곳을 먼저 정한다.
- 지난 라운드에서 넘어온 항목은 이번에 할지, 범위 밖으로 둘지 둘 중 하나로 적는다.
- 정하기 애매한 것은 spec 끝에 `## 사람이 정할 것` 으로 모은다.

## 4. 멈추기
- 코드, 테스트, `plan.md`, SSOT, ROADMAP 은 **쓰지 않는다**.
- 사람에게 spec 요약(목표, 요구사항 핵심, 범위 밖, 사람이 정할 것)을 보여 주고 승인을 기다린다.
- 승인을 받으면 다음 단계는 `round-plan` 이라고 알려 준다. 수정 요청을 받으면 spec 만 고치고 다시 기다린다.
