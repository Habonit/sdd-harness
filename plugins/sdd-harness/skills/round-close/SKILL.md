# round-close · 정리 → SSOT → 종료 조건 점검 → 완료 표시

## 0. 규칙 먼저
- 프로젝트 루트의 `CLAUDE.md` 를 읽는다. **라운드 종료 조건은 `CLAUDE.md` 에 적힌 것이 기준이다.** 이 스킬은 조건을 따로 정하지 않는다.
- `CLAUDE.md` 에 라운드 종료 조건이 없으면 멈추고 사람에게 알린다.

## 1. 대상 라운드와 전제 확인
- 인자로 라운드가 주어졌으면(`$ARGUMENTS`) 그 라운드, 아니면 `docs/ROADMAP.md` 에서 상태가 `완료` 가 아닌 첫 라운드.
- `docs/roundNN/review.md` 에 검증 결과와 조치가 있어야 한다. 없으면 멈추고 `round-build` 를 먼저 하라고 알린다.

## 2. 정리 (cleaner 에이전트)
- `cleaner` 서브에이전트(이 플러그인의 `sdd-harness:cleaner`)를 부른다. 프롬프트에 라운드 번호, 이번 라운드에서 바꾼 파일, `docs/SSOT.md` 경로를 넣는다.
- cleaner 가 "사람이 판단할 것" 으로 돌려준 항목은 지우지 않고 사람에게 보여 준다.
- 정리 후 `CLAUDE.md` 의 테스트 · 린트 명령이 정리 전과 똑같이 통과하는지 직접 확인한다.
- `review.md` 에 `## 정리 (cleaner)` 절을 쓴다: 찾은 것, 지운 것 · 고친 것, 남긴 것과 이유.

## 3. SSOT 갱신
- `docs/SSOT.md` 를 지금 코드와 대조해 고친다. 최소한:
  - 현재 라운드 표시
  - API 목록 (없어진 것은 지우고, 새로 생긴 경로 · 파라미터 · body 필드를 더한다)
  - 데이터 모델 (필드, 타입, 기본값, 응답에만 있는 필드)
  - 규칙 (이번 라운드에서 정한 검증 규칙, 아직 남은 어긋남)
- `CLAUDE.md` 가 SSOT 에 더 적으라고 정한 항목이 있으면 그것도 한다.

## 4. 종료 조건 점검
- `CLAUDE.md` 의 라운드 종료 조건을 **번호 순서대로 하나씩** 확인한다. 조건마다 실제로 확인한 근거를 남긴다.
  - 명령이 있는 조건은 직접 실행하고 결과(예: `N passed`, exit code)를 적는다.
  - 문서 일치 조건은 문서와 코드를 실제로 대조한다. 기억에 기대지 않는다.
- ROADMAP 완료 표시처럼 이 단계에서 해야 끝나는 조건은 다른 조건이 모두 지켜진 뒤 마지막에 처리한다.
- 하나라도 안 지켜졌으면:
  - 고칠 수 있으면 고치고 그 조건부터 다시 점검한다.
  - 고칠 수 없으면 ROADMAP 을 바꾸지 않고 멈춰서, 어떤 조건이 왜 안 되는지 사람에게 보고한다. "끝났다" 고 말하지 않는다.

## 5. 완료 표시와 기록
- 모든 조건을 지켰을 때만 `docs/ROADMAP.md` 의 이번 라운드 상태를 `완료` 로 바꾼다.
- `review.md` 에 이어서 쓴다:

```
## 다음 라운드로 넘기는 것
## 종료 조건 점검      (CLAUDE.md 조건 번호마다: 지킴 / 안 지킴 + 근거)
→ roundNN 완료.

## 회고
### Hook 이 막은 것
### verifier 가 지적한 것
### cleaner 가 지운 것
### 다음 라운드에 추가할 규칙 (제안)
```

- 회고에서 제안한 규칙은 `CLAUDE.md` 에 직접 넣지 않는다. 사람이 정하도록 제안으로만 남긴다.

## 6. 보고
- 사람에게 종료 조건 점검표와 다음 라운드로 넘기는 것을 보여 준다.
- 다음 라운드는 `round-start` 로 시작한다고 알려 준다.
